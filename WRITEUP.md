# Alignment Does Not Compose: Governed Execution Forests for Agent Swarms

## Abstract

Per-agent alignment and per-agent governance do not compose to swarm-level safety. We show this constructively. Each agent in a small deterministic swarm runs as an individually governed execution tree under pollard, with its own budget and policy. Every agent follows the same locally rational rule: delegate work instead of doing it, because delegation is cheaper for the delegator than local work. No agent breaks its own rules, yet the ungoverned swarm spends 651 credits against a 300 credit reference pool and delegates to depth 4, because the cost of a delegation lands on other agents and on the collective. The remedy is also at the execution layer. Treating the swarm as a forest, with each delegation edge recorded as a governed action in the delegator's tree, one shared budget pool across all trees, and a depth gate with an approval step, contains the same swarm at 251 credits and depth 2. A drift layer built on epicormic sequential detectors watches a per-agent action-cost stream; when one agent's work cost is multiplied by 4 mid-run, the detector alarms on the first inflated action with no false alarm before onset, a drift verdict is recorded in the epicormic ledger, the agent is frozen, further delegations are refused by epicormic's DriftMeter, and the run completes at 281 credits. In all three conditions the recorded forest replays exactly: the replayed decision and edge trace has the same SHA-256 digest as the recorded trace, and replay invokes no step functions.

## 1. Problem: governance that stops at the agent boundary

Agent governance tooling is mostly scoped to a single run: a budget for this run, a policy for this run's tool calls, an approval gate in front of this run's side effects. A swarm is a set of such runs that hand work to each other. The failure mode studied here is compositional. Delegation moves cost across the boundary that per-run governance watches. The delegator pays a small fee and stays inside its own budget; the delegatee absorbs the work; the total grows with the number of edges, not with any single agent's spend. Depth compounds it: a sub-item delegated twice is outside the depth accounting of every individual tree that touched it, because each tree only sees its own edges.

The experiment isolates this failure with deterministic agents. Determinism is a design choice, not an oversight: it makes the execution trace exactly replayable, so the governance claims below are checkable against recordings rather than argued from samples. Section 4 states what this does and does not generalize to.

## 2. Construction

**Trees.** Each agent owns one pollard run. Local work is a `model_call` node on the agent's run, priced in credits by a meter. Everything an agent does, including every refusal it hits, is a node in its own content-addressed tree, which pollard can verify and replay.

**Forest and governed edges.** Delegation is a registered pollard action named `delegate`, executed as a `tool_call` on the delegator's run. The edge therefore exists as a node in the delegator's tree, carrying the target agent, the child item, and the delegation depth. The swarm is the forest of the agents' trees plus these edges, and an edge is subject to the same machinery as any governed action: policy decision, approval gate, budget precheck, recorded refusal on denial.

**Shared pool.** Governed conditions bind one pollard `SharedBudget` named `pool` across all runs in a transactional SQLite store, with a per-run sub-allocation on top. A charge by any agent settles against the pool; an action that would exceed the pool or the acting agent's sub-allocation is refused before dispatch and recorded as a refusal node.

**Delegation gate.** A pollard `Policy` implementation evaluates every `delegate` call with swarm-level state: delegations from frozen agents are denied; delegations beyond a per-agent spawn limit are denied; delegations creating an edge deeper than the maximum depth (2 in the experiment) are denied; delegations creating an edge exactly at the maximum depth require confirmation under pollard's approval flow. The driver acts as approver and confirms only while the pool retains at least 25 percent of its capacity. A split whose delegation is refused is abandoned: the delegator works the item locally, and sub-items never dispatched are covered by that local work.

**Drift layer.** The drift condition adds a monitor over the watched agent's executed action costs, in execution order (delegation fees and work charges). Detection uses epicormic's sequential detectors, `page_hinkley` as the primary rule and `cusum` as a cross-check, evaluated on the stream prefix after each new sample. On the first Page-Hinkley alarm the swarm layer assembles an epicormic verdict document from the detectors' output (state `drift`, rule `page_hinkley`, both sequential states) and records it through epicormic's `record_verdict`, so the verdict sits in the monitor chain and the epicormic `Ledger` reports state `drift`. Two containment levers then act. epicormic's `DriftMeter`, registered on the runtime for tool calls, refuses every further delegation swarm-wide while the ledger state is `drift`. The delegation gate freezes the drifting agent, and the driver reassigns its queued items to other agents.

**What calls which API.** pollard provides the runtime, trees, registry, policy and confirmation flow, budget scopes including the shared pool, the meter protocol, `recompute_charges`, `verify`, and replay. epicormic provides the two sequential detectors, the verdict and ledger machinery (`Monitor`, `Verdict`, `record_verdict`, `Ledger`), and the `DriftMeter` lever. The swarm layer implements the agents and task economy, the assignment rule, the gate's rule set as a pollard policy, the approver rule, the refused-split fallback, the forest recorder and its trace digest, the drift stream, and the verdict document assembly. Two available primitives were deliberately not used. pollard's team delegation helpers bind sub-runs under a team runtime; here the edge had to be a governed node in the delegator's own tree, which the registered-action route expresses directly. epicormic's probe panel and scorer pipeline sample model endpoints; the monitored stream here is swarm telemetry, not probe responses, so the verdict document is assembled from the sequential detectors and recorded through the same ledger path, with the vacuous subjective-logic opinion because no panel opinion is computed. epicormic's `DriftPolicy` and `ContractGate` levers were not used.

## 3. Experiment

**Setup.** Five deterministic agents: atlas (coordinator and entry point), gale (aggressive), birch, cedar, dune. Workload: 3 root items with `splits = 4`. An item with splits remaining can be split into sub-items with one less split, or worked locally at cost `6 + 2 * splits` credits (6 to 14). Delegation costs the delegator a fee of 1 credit per edge. Fanout is 3 for atlas and gale, 2 for the others. Every agent delegates when it can, because delegating costs at most 3 credits against 6 to 14 for local work; this is the locally rational rule. Non-aggressive agents stop splitting at depth 3; gale splits at any depth. Sub-items are assigned round-robin across the roster by creation order. Governed parameters: pool 300 credits, sub-allocation 100 credits per agent, maximum delegation depth 2, spawn limit 60 per agent. Drift condition: gale's work cost is multiplied by 4 starting from its seventh executed action; Page-Hinkley with delta 1.0 and threshold 6.0, minimum 5 samples; CUSUM reference and threshold set from the pre-onset baseline. Task success means every root item resolves and total spend stays within the pool. Replay re-runs the same driver against the recorded store in pollard HYBRID mode and compares forest recorder digests.

**Results.**

| Metric | Ungoverned | Governed | Governed + drift |
| --- | --- | --- | --- |
| Total spend (credits) | 651 | 251 | 281 |
| Pool (credits) | 300 (reference) | 300 | 300 |
| Max delegation depth | 4 | 2 | 2 |
| Gate denials | 0 | 22 | 22 |
| Confirmations requested / approved | 0 / 0 | 22 / 22 | 22 / 22 |
| Budget refusals | 0 | 0 | 0 |
| Drift refusals | 0 | 0 | 1 |
| Items resolved / created | 120 / 120 | 34 / 87 | 34 / 84 |
| Task success | no | yes | yes |
| Replay trace digest match | yes | yes | yes |

Ungoverned, the delegation cascade is the whole story: every item splits whenever its owner can split, 120 items are created, all roots complete, and the swarm spends 651 credits, 2.17 times the reference pool, reaching delegation depth 4. No individual agent misbehaves. Each delegation was the cheapest action available to its delegator.

Governed, the same economy is contained by structure rather than by exhortation. The depth gate denies 22 split attempts at the boundary; items whose splits are refused are worked locally by their owners; 53 proposed sub-items are never dispatched. The approval gate is exercised 22 times at depth 2 and the approver confirms all 22, because pool headroom stays above the 25 percent floor at those points. Total spend is 251 credits and depth is capped at 2. In this parameter regime the depth gate binds before the budget scopes do: the pool and the sub-allocations refuse nothing in the scenario runs. Pool refusal, including refusal of one agent's action because another agent spent the pool down, is covered by the unit tests against a small pool rather than by these runs. The spawn limit of 60 also never binds.

In the drift condition, gale's stream before onset is six delegation fees of 1 credit. Its seventh executed action is the first inflated work charge, 40 credits against a normal 10. Page-Hinkley alarms at stream index 6, the same index as onset: detection delay 0 steps, where a step is one executed action of the watched agent. CUSUM alarms at index 6 as well. Neither detector alarms on the pre-onset prefix. The verdict is recorded in the epicormic ledger, gale is frozen with 4 queued items reassigned, and a post-verdict delegation probe by atlas is refused by the DriftMeter. Exactly one inflated action lands before containment, putting total spend at 281 credits, still inside the pool.

Replay holds in all three conditions. The replayed trace digest equals the recorded digest, replay invokes zero step functions (every executed call resolves from its recording; refusals re-derive from the same policy and budget state), pollard `verify` passes on every agent chain, and the spend recomputed from the store by pollard's `recompute_charges` equals the recorder's total in every condition.

## 4. Limitations

The agents are deterministic scripts. The results show governance mechanics (accounting, gating, detection, containment, replay) and one compositional failure mode; they say nothing about how LLM-driven agents would behave under the same gates, and nothing about strategic adaptation to the gates. The task family is a single split-or-work item tree; other delegation topologies (shared subgoals, cyclic handoffs, negotiation) are untested. Drift is injected synthetically as a cost multiplier on one agent at a known point; real provider or behavior drift will be noisier, and the zero-delay detection here reflects a large, abrupt shift (a factor of 4) against a quiet baseline of 1 credit fees. The swarm is small: 5 agents, at most 120 items. As noted in Section 3, the depth gate binds first in this regime, so the budget scopes act as a backstop whose refusal behavior is unit-tested, not measured in the scenario runs. Replay uses HYBRID mode because a refused call leaves a refusal node rather than a call recording, so pure REPLAY mode has nothing to resolve for refused actions; exactness is therefore claimed at the level of the decision and edge trace with zero step function invocations, which is the level the trace digest measures.

## 5. Related position

The position taken here is that swarm governance is an execution-layer property, not a property of any agent framework's prompt or planning loop. If delegation is an action in a recorded execution tree, if the accounting unit is the pool rather than the run, and if behavior streams are monitored with sequential detectors wired to fail-closed levers, then the controls are framework-independent: they bind whatever produced the actions. That is the same bet pollard makes for single runs and epicormic makes for provider drift, extended one level up, from the tree to the forest. The non-composition result is the reason the extension is necessary: governing every tree in the forest, one at a time, leaves the edges ungoverned, and the edges are where the failure lives.
